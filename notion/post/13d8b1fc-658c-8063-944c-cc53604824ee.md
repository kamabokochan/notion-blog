
# CloudFront Functions

- リクエストやレスポンスに対して軽量なロジックを実行できる
- 主な用途
	- HTTPリクエストのヘッダー、URLパス、クエリパラメータの変更
	- 簡単な認証やアクセス制御の実装
	- キャッシュキーのカスタマイズ
- サポートしている言語
	- JavaScript

# Lambda@Edge

- AWS Lambda関数をCloudFrontの各エッジロケーションで実行するためのサービス
- CloudFront Functionsよりも高度で複雑な処理が可能で、オリジンサーバーにリクエストを送信する前や、エンドユーザーにレスポンスを返す前に実行することができる
- 主な用途
	- リクエストやレスポンスのカスタム認証
	- コンテンツの動的生成や変更
	- ユーザーに応じたパーソナライズ（例：ユーザーの場所やデバイスに基づく動的HTMLの生成）
	- キャッシュの管理とカスタマイズ
- サポートしている言語
	- Node.js
	- Python

# どちらを選ぶべきか

- CloudFront Functionsは軽量でシンプルな操作（ヘッダーやURLの書き換えなど）に最適
- Lambda@Edgeは、より複雑な操作や、データの操作が必要な場合に向いている。

```typescript
exports.handler = async (event) => {
    const request = event.Records[0].cf.request;
    const userAgent = request.headers['user-agent'][0].value.toLowerCase();

    // User-Agentに基づいてPC/SPのFargateオリジンを決定
    let targetOrigin;
    if (userAgent.includes('mobile') || userAgent.includes('iphone') || userAgent.includes('android')) {
        // SP用のオリジン（SP向けコンテンツを提供するFargateサービス）
        targetOrigin = 'sp-alb.example.com'; // SP用Fargateサービスを指すALBのDNS名
    } else {
        // PC用のオリジン（PC向けコンテンツを提供するFargateサービス）
        targetOrigin = 'pc-alb.example.com'; // PC用Fargateサービスを指すALBのDNS名
    }

    // CloudFrontのリクエストターゲットを変更
    request.origin = {
        custom: {
            domainName: targetOrigin,
            port: 443,
            protocol: 'https',
            path: '', // 必要に応じてパスを追加
            sslProtocols: ['TLSv1.2'],
            readTimeout: 5,
            keepaliveTimeout: 5,
            customHeaders: {}
        }
    };
    request.headers['host'] = [{ key: 'host', value: targetOrigin }];

    return request;
};

```
