## Dockerfileの作成


```docker
# 1. ベースイメージとしてNode.jsを使用
FROM node:22 AS build

# 2. コンテナの作業ディレクトリを設定
WORKDIR /app

# 3. package.jsonとpackage-lock.jsonをコピー
COPY package*.json ./

# 4. 依存関係をインストール
RUN npm install

# 5. Next.jsアプリケーションをコピー
COPY . .

# 6. Next.jsアプリケーションをビルド
RUN npm run build

# 7. 本番環境用の軽量なイメージを使用
FROM node:22-slim

# 8. 作業ディレクトリを設定
WORKDIR /app

# 9. 依存関係をコピー（ビルドした結果をコピー）
COPY --from=build /app ./

# 10. 本番環境用のNext.js実行に必要な依存関係をインストール
RUN npm install --production

# 11. Next.jsが提供するサーバーを実行するポートを公開
EXPOSE 3000

# 12. SSRサーバーの起動コマンド
CMD ["npm", "start"]
```

- `COPY <source> <destination>`
	- **`<source>`**: コピー元のパス
	- **`<destination>`**: コピー先のパス
- マルチステージビルド
	- 1つの Dockerfile で複数のビルドステージを定義し、最終的に不要なビルド環境をイメージに含めずに、軽量で効率的な最終イメージを作成するための方法。
	- 最初の `FROM node:22`
		- このベースステージは、アプリケーションの依存関係をインストールし、Next.js アプリケーションをビルドするための作業を目的としている。
	- 次の `FROM node:22-slim`
		- 本番用の軽量なイメージを作成する。
- ビルドコマンド

	```bash
	docker build -t nextjs-ssr-app .
	```

- コンテナ起動

	```bash
	docker run -p 3000:3000 nextjs-ssr-app
	```

	- [http://localhost:3000](http://localhost:3000/) で確認する

## メモ


### ネットワークについて

- ドメイン間通信とコンテナ間通信の両方を受け入れる必要があるかどうか
	- ドメイン間通信
		- Next.jsサーバーとAPIサーバーが同じオリジンで動作しない場合は必要。

		例:

		- Next.js: `https://frontend.example.com`
		- APIサーバー: `https://api.example.com`
	- コンテナ間通信
		- APIサーバーがインターネット上で公開されており、Next.jsサーバーが外部URLを通じてAPIサーバーにアクセス可能な場合は、不要
